Для UI-библиотеки так делать нельзя без явного согласования, особенно когда цель — проверить и довести загруженные компоненты, а не редизайнить их.

Честная оценка: да, я смогу восстановить такие нижние закругления и исправить исходный баг без отката всего проекта. Это CSS-задача со стабильным решением: активной вкладке нужны декоративные псевдо-/внутренние элементы слева/справа, но они должны быть рассчитаны одинаково для первой, средней и последней вкладки, без изменения высоты первой вкладки и без отрицательных вертикальных смещений, которые ломали старый вариант. Риск есть только в точном попадании в исходную форму по пикселям; функционально и визуально близко к картинке 2 сделать могу.

План:

1. Восстановить декоративную модель TabsRounded
   - Вернуть контролируемые элементы/псевдоэлементы для нижних скруглений активной вкладки.
   - Для первой вкладки показывать нижнее скругление справа/переход к соседней вкладке и сохранить левую нижнюю вертикальную грань как на примере.
   - Для центральных вкладок показывать оба нижних перехода — слева и справа.
   - Для последней вкладки показывать нижний переход слева.

2. Исправить исходную причину кривизны
   - Не возвращать старое `height: 64px` только для первой вкладки.
   - Не использовать `margin-bottom: -20px`, из-за которого ряд съезжал.
   - Выровнять все вкладки по одной базовой линии и одной высоте.
   - Оставить перекрытие вкладок по горизонтали, но не ломать вертикальную геометрию.

3. Сделать геометрию зависимой от позиции вкладки
   - Добавить классы состояния: первая/последняя/активная вкладка.
   - В компоненте вычислять, какие декоративные элементы нужны активному табу.
   - Сохранить публичный API компонента без изменений.

4. Проверить на демо
   - Кликнуть `Обзор`, `Данные`, `Настройки`.
   - Сравнить визуально с твоей второй картинкой: активный таб должен быть белым, с синим текстом, соседние серые табы должны заходить под него, а нижние закругления должны быть видны в нужных местах.

5. Проверить сборку
   - Запустить сборку библиотеки и демо.
   - Если после правки окажется, что форма отличается от исходной слишком сильно, лучше остановиться и честно сказать, что нужен точный CSS-референс/исходный дизайн, а не продолжать тратить токены на угадывание.

Я не предлагаю полный откат, потому что текущая версия уже устранила главный layout-баг. Правильнее восстановить декоративные элементы поверх стабильной базы, а не возвращать старую сломанную высоту первой вкладки.
