План реализации нового select-компонента с диалогом выбора

## Что будет добавлено

1. Новый компонент на базе текущего `Select`
   - Добавлю отдельный компонент, например `DialogSelect`, рядом с текущим `Select`.
   - Он сохранит похожую модель данных через `CustomOption<T, S>` и привычные props: `value`, `placeholder`, `label`, `onChange`, `onClear`, `disabled`, `error`.
   - Внешний вид закрытого поля будет как на рис. 1: слева placeholder/выбранное значение, справа текстовая кнопка `Выбрать`.
   - При клике по полю или по `Выбрать` будет открываться модальное окно.

2. Диалог выбора
   - Использую `src/components/ui/dialog.tsx` как основу, но визуально подгоню под текущую библиотеку.
   - Сделаю диалог ровнее и аккуратнее, чем на скриншоте:
     - центрирование;
     - одинаковые внутренние отступы;
     - аккуратный радиус;
     - затемнённый фон;
     - фиксированная максимальная ширина;
     - шапка с заголовком;
     - область таблицы с прокруткой;
     - нижняя панель действий без наложения на список.
   - Кнопки внизу: `Добавить вручную` опционально через prop, `Закрыть` всегда.

3. Поиск и фильтрация на сервере
   - Внутри диалога будет строка поиска как на рис. 2.
   - Ввод будет менять search state компонента.
   - Компонент будет вызывать переданный async-загрузчик данных, например:
     ```ts
     loadOptions({ search, page, pageSize })
     ```
   - Фильтрация будет именно внешней/серверной: компонент сам не будет фильтровать уже загруженный массив локально.
   - Добавлю debounce для поиска, чтобы не отправлять запрос на каждый символ мгновенно.

4. Пагинация
   - Компонент будет поддерживать постраничную загрузку:
     - `page`;
     - `pageSize`;
     - `total` или `hasNextPage`;
     - кнопки `Назад` / `Вперёд`;
     - отображение текущей страницы.
   - При изменении поискового запроса страница будет сбрасываться на первую.
   - Во время загрузки будет показываться `Spinner`, а пустое состояние — через `EmptyComponent`.

5. Таблица результатов
   - По умолчанию сделаю таблицу с колонками `ФИО сотрудника` и `День рождения`, как на скриншоте.
   - Чтобы компонент был переиспользуемым, колонки будут настраиваться через props:
     ```ts
     columns={[{ key: 'name', title: 'ФИО сотрудника', render: option => option.label }]}
     ```
   - Клик по строке будет выбирать option, вызывать `onChange(option)` и закрывать диалог.
   - Активная выбранная строка будет визуально подсвечиваться.

6. Демо на главной странице
   - Добавлю пример в секцию `Select` на `/`.
   - Для демонстрации серверной фильтрации/пагинации сделаю mock loader с задержкой, который принимает `search`, `page`, `pageSize` и возвращает только нужную страницу данных.
   - В демо будет видно новый сценарий: поле как на рис. 1 → кнопка `Выбрать` → диалог поиска сотрудника.

## Технические детали

- Файлы, которые планирую добавить/изменить:
  - `src/lib/components/DialogSelect/DialogSelect.tsx`
  - `src/lib/components/DialogSelect/DialogSelect.module.scss`
  - `src/lib/components/index.ts`
  - `src/routes/index.tsx`
- Используемые существующие компоненты:
  - `Button`
  - `Label`
  - `InputCaption`
  - `Spinner`
  - `EmptyComponent`
  - `SearchIcon`
  - `Dialog` primitives из `src/components/ui/dialog.tsx`
- Текущий `Select` ломать не буду. Новый компонент будет добавлен отдельно, чтобы не рисковать существующей логикой dropdown-select.
- API сделаю generic-friendly, совместимым с текущим `CustomOption<T, S>`.

## Ожидаемый результат

На странице демо появится новый select в одну колонку. Он будет выглядеть как поле из первого скриншота, а при нажатии `Выбрать` откроет улучшенный диалог поиска сотрудника с серверной фильтрацией и пагинацией.
